 # Per-Actuator PWM Frequency, Volume Reset, and Event-Driven Checkpoints

  ## Summary

  - Configure each PWM channel’s frequency independently, with all 12 existing PWM actuators
    explicitly set to 24 Hz in server_info.py.

  - Let operators reset a pump’s live accrued-volume counter from its dashboard card without
    interrupting delivery.

  - Persist server configuration only when it changes; keep accrued-volume history durably only in
    PostgreSQL.

  ## Implementation Changes

  - Add pwm_frequency_hz to Channel, validate it as a positive integer for PWM outputs, and have
    PlcActuator pass that channel-specific value to analog_write_set_frequency. Explicitly set
    pwm_frequency_hz=24 on every pwm0–pwm3 channel for R0–R2.

  - Add a Dispenser operation that accrues delivery through the current instant, zeros total_volume,
    and preserves active duty and dose timing so delivery continues normally.

  - Expose reset_total_volume as a short OPC method on pump actuator nodes. It returns (accepted,
    message), refuses while calibration/autotune owns the actuator, immediately publishes the zero
    value, and does not trigger a configuration checkpoint.

  - Add a confirmed “Reset delivered” action beside Configure on applicable actuator cards. Keep its
    async handler directly attached and outside the refreshable readings subtree; disable it for
    read-only sessions and show server refusals or success notifications.

  - Remove total_volume from new server-state snapshots and recovery. Increment the snapshot schema,
    accept legacy schema-v1 snapshots to recover configuration while ignoring their saved totals,
    and always start restored counters at zero.

  - Remove the one-minute checkpoint loop, total-change signatures, conditional-total checkpoint
    API, and shutdown checkpoint. Retain immediate checkpoint callbacks for accepted changes to
    sampling period, pairings, control configuration, and autotune-applied gains.

  ## Public Interfaces

  - Channel.pwm_frequency_hz: per-output PWM frequency in Hz.
  - OPC actuator method: <reactor>:<actuator>:reset_total_volume() -> (bool, str).
  - New state snapshots omit actuator total_volume; legacy snapshots remain readable for
    configuration migration.

  ## Test Plan

  - Verify each configured PWM actuator initializes its pin with its own frequency, all current
    entries are explicitly 24 Hz, invalid frequencies fail clearly, and non-PWM outputs do not
    configure PWM frequency.

  - Verify volume reset banks elapsed delivery, zeros the counter, preserves an active dose, and
    accrues subsequent delivery from the reset instant.

  - Verify the OPC method publishes zero immediately, rejects calibration/autotune-owned pumps, and
    never invokes the state-change callback.
    actuator method, and the card’s controls survive periodic reading refreshes.

  - Verify schema-v2 snapshots contain no volume totals, restored counters start at zero, schema-v1
    configuration still restores while its totals are ignored, and malformed snapshots remain fail-
    safe.

  - Verify no periodic or shutdown checkpoint remains and every accepted configuration mutation
    still checkpoints exactly once.

  - Run the focused tests followed by uv run pytest.

  ## Assumptions

  - “Only in SQL” means accrued volume remains live in memory and exposed over OPC/GUI, while
    PostgreSQL is its only durable history.

  - Existing schema-v1 files are not rewritten merely by startup; the next configuration change
    replaces them with schema v2.

  - Reset is offered for pump actuators with a calibration slot, including currently unfitted pumps,
    and not for MFC actuators that cannot accrue calibrated volume.
